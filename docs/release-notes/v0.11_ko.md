# v0.11 — Optical Sampling & Numerical Accuracy Benchmark

**v0.11.0은 재사용 가능한 벤치마크·분석 프레임워크 릴리즈입니다.** 기존 KrF Scalar Abbe 모델을 유지하며 Source 적분, Mask Rasterization, Raw AI 보간의 오차와 계산 비용을 분리해 검증했습니다. 신규 계산 옵션의 Render 연결은 별도 검토 대상으로 남겼습니다. 현재 공개 데모의 Speed/Internal 옵션·기본값·화면은 [v0.10]({{ '/ko/release-notes/v0.10/' | relative_url }}) 동작을 유지합니다.

<h2 id="conclusions">1. 먼저 읽을 결론</h2>

**Exact Area + B-Spline을 유망한 조합으로 선정하되, Source 오차와 최초 Mask 준비 비용을 함께 봐야 합니다.** Dense7은 이번 정량 CD 연구 기준에 부족했습니다. 보통 후보는 Cell-area51 / Mask10 / AI25, 정밀 후보는 Cell-area51 / Mask5 / AI25입니다. 이 연구의 등급은 모든 Layout·공정의 오차 보증이나 현재 UI의 옵션명이 아닙니다.

| 구분 | Source Dense | 가중치 / 실제 Point | Mask nm | Raster | Native AI nm | 보간 | 최대 CD오차 nm | 최대 AI RMSE |
|---|---:|---|---:|---|---:|---|---:|---:|
| 기존 비교 조건 | 7 | Equal / 29 | 10 | Binary center | 10 | Bilinear | 56.2730 | 0.0525000 |
| 빠른 프리뷰 후보 | 7 | Equal / 29 | 25 | Exact Area | 25 | Cubic B-Spline | 15.3940 | 0.0147937 |
| 보통 후보 | 51 | Cell-area / 2077 | 10 | Exact Area | 25 | Cubic B-Spline | 1.3416 | 0.00109525 |
| 정밀 후보 | 51 | Cell-area / 2077 | 5 | Exact Area | 25 | Cubic B-Spline | 0.4403 | 0.000721803 |

이 표의 정확도는 **선택한 주기 L/S + Contact, nominal focus, raw T0=0.30 / D0=1**에서 연속 Source Reference와 비교한 최대값입니다. 기존·프리뷰는 공유 Mask/AI Phase, 보통·정밀은 독립 Phase sweep이므로 평가 범위도 함께 읽어야 합니다. Reference Crossing이 없는 Pattern은 CD=0으로 채우지 않고 status/RMSE/false printing으로 평가했습니다. 기존 조건에는 false-printing 사례도 있어 CD 숫자만으로 품질을 판정하면 안 됩니다.

보통의 연구 목표는 CD≤2nm/RMSE≤0.005, 정밀은 CD≤0.5nm/RMSE≤0.005입니다. 빠른 프리뷰는 이 정량 Gate를 만족하지 않습니다. 위 오차를 TT04PWM이나 실측 웨이퍼의 오차로 옮길 수 없습니다. 실제 TT04 시간은 [별도 표](#render)에서 비교합니다.

<h2 id="reference">3. Reference와 수치 검증</h2>

중심이0인 무한 주기 Binary L/S의 Fourier 계수는 `c_m = (W/P) sinc(mW/P)`입니다. 각 Source `(sx,sy)`에서 `(m/P−sx)²+sy² ≤ (NA/λ)²`를 만족하는 회절차수만 합해 field와 intensity를 계산합니다. Mask Rasterization과 불필요한2D FFT를 거치지 않는 Reference입니다.

Nominal focus의 연속 균일 원형 Source 적분은 Source disk와 두 회절차수의 shifted pupil disks가 겹치는 면적으로 구성했습니다. 원 경계 교차점을 breakpoint로 둔 adaptive 적분과 독립 quadrature/고밀도 Source를 교차 확인했습니다. Dense201이나 가장 작은 Pixel을 정답으로 가정하지 않았습니다.

| 비교 | 검증하는 오차 |
|---|---|
| R0: 정확한 Geometry Fourier + 연속 Source | 기준 모델의 수치 Reference |
| R1 ↔ R0 | 정확한 Mask, Discrete Source의 적분 오차 |
| R2 ↔ R1 | 같은 Discrete Source에서 Raster/DFT 표현 오차 |
| R3 ↔ R2 | 같은 Raw AI Sample에서 보간 오차 |
| R3 ↔ R0 | End-to-end 종합 오차 |

단계 오차를 더하거나 빼서 인과적 기여율로 해석하지 않습니다. Reference는 여전히 Scalar 모델의 수치 기준이며 실측 광학·Resist 기준이 아닙니다. Source 적분 tolerance를 좁힌 초기1D 검증에서 AI 변화5.55e−17을 관측했지만, 적분기의 오차 추정을 범용 보증으로 해석하지 않습니다.

초기 전수 교차검증은 비정수 Pitch/Pixel 조건4곳에서 실패했습니다. 원래 grating 회절차수만 사용하면 Raster aliasing이 만든 supercell 저주파 성분을 놓치는 문제였습니다. DFT의 전체 광학 통과 성분을 포함하도록 **Benchmark 축약 계산**을 수정해160blocks/20,480행을 다시 계산했습니다. 초기 실패와 수정 기록을 보존했습니다. Production 모델 수정은 없습니다.

최종342개 실제2D Abbe 교차검증의 최대 잔차는9.80e−13, 허용오차1e−10입니다. Native Binary216조건의 Mask 비교는 불일치0이었습니다. 보통 후보의 추가2D 교차검증 잔차는 L/S1.09e−14, Contact9.60e−15입니다.

<h2 id="source">4. Conventional Source Sampling 수렴</h2>

Dense는 정사각형 격자의 한 변 설정이며 실제 Source Point 수가 아닙니다. 기존 Equal 방식은 원 안에 들어오는 Node에 같은 weight를 줍니다. **Cell-area는 같은 균일 원형 Source를 적분하는 quadrature**이며, 원 경계에 걸친 Cell의 면적과 대표 Node 처리가 달라집니다. 일부 Node는 원 경계로 radial projection하고 실제 Point 수도 바뀝니다. 실측 장비의 비균일 Source 분포나 weight만 바꾼 대조 실험이 아닙니다.

<h2 id="raster">5. Mask Rasterization</h2>

Binary center sampling은 기존 경계 포함 규칙을 재사용했습니다. Exact Area는 Pixel과 Polygon의 교차 면적을 Pixel 면적으로 나눈 coverage입니다. 연속 Binary Mask의 평균 amplitude 표현이며 실제 Gray Mask를 새로 도입한 것이 아닙니다. Polygon hole과 Subpixel Translation, Periodic Boundary·면적 보존을 테스트했습니다.

SSAA2×2/4×4/8×8은 고해상도 Binary sample의 평균이며 Exact Area에 대한 근사입니다. 유한 factor의 수렴은 비단조일 수 있습니다. 같은 subpixel sample의 MSAA는 중복 구현하지 않았고, Box/Area averaging은 Exact Coverage와 중복됩니다. Gaussian smoothing이 Optical 정확도를 개선한다고 가정하지 않았습니다. Bandlimited Oracle는 음수·1초과 amplitude를 허용하는 진단 기준으로 제품 Raster 후보에서 제외했으며 FXAA는 사용하지 않았습니다.

판정은 Mask 외관보다 Optical passband 성분과 R2↔R1 AI/CD를 우선했습니다. Binary는 phase 양자화와 false printing을 보였고 Exact Area는 오차를 크게 줄였습니다. 다만 면적 보존만으로 유효 Fourier 성분이나 CD가 정확해지는 것은 아니며, Area25nm가 정밀 조건을 대체하지도 않았습니다.

![Raster별 조건부 오차와 Pixel 비교]({{ '/assets/release-notes/v0.11/02_full_raster_stage.png' | relative_url }})

일반 TT04 Polygon의 현재 Area 구현은 모든 Pixel을 순회하므로 준비 비용이 큽니다. L/S 전용 interval overlap의 빠른 시간을 실제 Layout 준비 비용으로 적용하면 안 됩니다. 경계 Cell에 계산을 집중하는 최적화와 Mask/FFT cache가 제품 적용의 우선 과제입니다.

<h2 id="interpolation">6. Raw AI 보간과 Blackman Radius</h2>

동일 Raw AI samples를 모든 방법에 입력했습니다. Threshold를 먼저 적용한 Binary Image의 보간이 아닙니다. Keys Bicubic(`a=−0.5`)과 prefilter를 사용하는 Cubic B-Spline을 구분했고, sinc는 finite weight sum을 정규화했습니다. Blackman은 R2/R4/R8을 비교했습니다. 이 실험의 boundary는 periodic extension이며 overshoot·negative intensity·ringing을 자동 제거하지 않았습니다.

|---|---:|---:|---|
| Nearest | 22.9658 | 23.1144 | 실패 |
| Bilinear | 7.8710 | 7.7809 | 실패 |
| Keys Bicubic | 0.6732 | 0.2383 | 실패 |
| Cubic B-Spline | 0.4403 | 0.0324 | 통과 |

<h2 id="split-grid">7. Fine Mask / Coarse AI: 주요 성능 개선</h2>

Production은 여전히 Mask와 Native AI가 같은 FFT Grid를 공유합니다. Benchmark adapter는 **Fine Mask FFT의 통과 성분을 같은 Physical Domain의 작은 Field FFT로 옮겨** Mask와 AI Pixel을 분리했습니다. 단순한 출력 downsampling이나 Coarse Mask 재생성이 아닙니다.

2D FFT 정규화 `(Nout/Nmask)²`와 Pixel-center origin의 위상을 보정하고, `Nyquist_AI > max(NA/λ + source_radius, 2NA/λ)`를 확인했습니다. 주파수 간격 `1/domain`과 유효 shifted-pupil 성분을 유지한 뒤 기존 Abbe compute를 그대로 호출합니다.

| Source / Mask·AI nm / B-Spline | 최대 CD오차 nm | 최대 RMSE | L/S 광학 s | Contact 광학 s |
|---|---:|---:|---:|---:|
| Cell-area51 / 5·5 | 0.4350 | 0.000712 | 18.1387 | 3.1284 |
| Cell-area51 / 5·25 | 0.4403 | 0.000722 | 0.5256 | 0.1093 |
| Cell-area51 / 10·25, 보통 | 1.3416 | 0.001095 | 0.5208 | 0.1160 |
| Equal101 / 5·25 | 0.4593 | 0.000280 | 1.9451 | 0.4298 |

시간은 Cloud의 실제2D Abbe **median3 warm call**, L/S3µm·Contact1.2µm, Mask 준비·출력 제외입니다. 첫 행과 독립 Grid 행의 Phase 범위가 다르므로 미세한 오차 차이를 직접적인 알고리즘 우열로 읽지 않습니다. 같은 Fine Mask/Source에서 광학 계산만 L/S약34.5배, Contact약28.6배 절감했습니다. **전체 웹 요청의 속도 향상 배수는 아닙니다.**

![실제 Fine/Coarse Field 광학 시간]({{ '/assets/release-notes/v0.11/07_split_grid_runtime.png' | relative_url }})

<h2 id="cross">8. Grid Phase·Cross Evaluation·변수–Metric 분석</h2>

Mask와 AI Phase는0/0.25/0.5/0.75 pixel을 독립 적용했습니다. Contact에서는 Mask16개 XY Phase × AI16개 XY Phase =256쌍을 비교했습니다. 물리 좌표를 정렬하고, Quarter Phase를 정확히 표현하는 Benchmark 전용0.025nm DBU와 float 평가 좌표를 사용했습니다. Production0.1nm DBU는 유지합니다.

![Grid Phase에 따른 오차]({{ '/assets/release-notes/v0.11/05_full_grid_phase.png' | relative_url }})

전수 결과에는 종합 Gate를 만족해도 단계 Gate를 실패한3,114행이 있었습니다. 예를 들어 LS137/Dense21/Area20의 종합 CD오차0.0856nm에는 Source1.5660nm와 Raster1.4782nm 조건부 오차의 상쇄가 포함됩니다. 최종 CD 숫자만 작은 조합을 최적점으로 선정하지 않습니다.

![단계 오차 상쇄 진단]({{ '/assets/release-notes/v0.11/06_error_cancellation.png' | relative_url }})

조건표는 사례·Source·Weighting·Mask/AI Pixel·Raster·보간·Radius·독립 Phase·Reference·상태를 기록합니다. Phase별 max/p95/median으로 묶은28,032설정과 **다른 변수·Phase 집합을 고정한115,920비교 쌍**, 실제 후보의 변수 편차300행을 생성했습니다. 음의 Error Delta는 개선이며, 설정에 따른 표준편차를 반복 측정의 신뢰구간으로 해석하지 않습니다.

Runtime은 Fourier 축약 계산, 실제2D Abbe, 일반 Layout Raster, 전체 HTTP를 구분했습니다. Canonical 조건과 모든 물리 설정·Phase가 일치하는295행에만 실측 시간을 연결했고 미측정 값은 빈칸입니다. Pattern별 허용 오차·Crossing 상태·단계 Gate를 먼저 정한 뒤, **같은 작업 범위의 실측 Runtime**으로 Pareto를 비교해야 합니다. 한 가지 범용 Pareto 최적점을 확정하지 않았습니다.

![Raster·보간 조합별 오차]({{ '/assets/release-notes/v0.11/04_full_cross_heatmap.png' | relative_url }})

Contact의 보간 RMSE가 평가 mesh의 우연한 정렬로 작아질 가능성도 확인했습니다. 추천 B-Spline의256개 독립 Phase를10/5/2/1nm 공통 평가점으로 다시 평가했고, AI25의 worst Contact RMSE는10nm에서7.98378e−5, 1nm에서7.98340e−5였습니다. CD는 별도의 threshold crossing 탐색으로 계산합니다.

<h2 id="render">9. 실제 TT04PWM와 Render 실행 가능성</h2>

67/20과68/20 모두 실제 TT04PWM에 존재합니다. 67/20은 등록된170nm 기준(147.770,108.460)µm/y를 사용했습니다. 68/20은 실제 Geometry의140nm gauge(129.490,91.3125)µm/x를 검증해 자원만 측정했습니다. **68/20의 자동 Reference 등록을 추가한 것은 아닙니다.** 현재 UI에서는 유효한 Custom Anchor가 필요합니다.

`render.yaml`은 Free·Gunicorn1worker·timeout300s입니다. [공식 Free 사양](https://render.com/docs/compute-plans)은0.1CPU/512MB이며, 아래는 같은 수준인 **Docker0.1CPU/512MiB/swap없음**에서의 실측입니다. 실제 Render Dashboard의 현재 CPU·RAM·배포 SHA를 조회하거나 새 후보를 배포하지 않았습니다.

| 옵션 | 67/20 1ROI s | 68/20 1ROI s | 현재 앱·Free 판단 |
|---|---:|---:|---|
| 기존 | 2.125 | 1.427 | 기존 경로 지원. 68은 Custom Anchor 필요 |
| 빠른 프리뷰 | 3.000 | 2.021 | Area/B-Spline 연결 후 적용 후보 |
| 보통 | 19.118 | 18.191 | 연결 후 단일 초점·소수 ROI부터 검증 |
| 정밀 | 51.107 | 49.101 | 별도 Mask cap640 필요. 캐시·한두 ROI 권장 |

이 시간은 동일3.2µm domain의 **GDS read/clip·Raster·FFT·Source·nominal Abbe·Gauge**입니다. Source는 설정별 첫 생성 후 재사용했습니다. Python import, DRC 후보 추출, D0 calibration, Contour/그림/CSV/GDS/HTML 출력·네트워크를 제외했으므로 전체 서비스 TAT가 아닙니다. Quota는1회, Native 광학은median3이며 CPU quota period의 burst 때문에 짧은 wall time의 순위는 불안정합니다.

**프리뷰의 최초 계산은 이번 TT04에서 기존보다 약1.4배 느렸습니다.** 일반 Polygon의 Exact Area 준비 때문입니다. 준비된 Mask/FFT를 재사용하면 광학 계산은 약8–9배 빠릅니다. 보통·정밀은 Source와 AI Grid가 같아 반복 광학 비용은 비슷하고, Mask 준비가 큰 차이를 만듭니다. 계산 adapter의 quota 누적 peakRSS는145.1MiB 이하였습니다.

기존 Speed의 **전체 Gunicorn HTTP 요청도 같은 quota에서119.899초·컨테이너 peak350.16MiB로 PASS**했습니다. Reference CSV nominalCD170.018074nm/D0.82421875를 검증했습니다. 이 fitting 잔차는 optical accuracy가 아닙니다. 전체 peak는 master/worker/client 및 charged page cache를 포함하므로 계산 worker RSS와 다릅니다.

초기 HTTP 검사는 화면에 나타나지 않는 내부 ID를 찾다가 실패했습니다. 실제 결과 CSV는 정상이었고, 검사를 다운로드 CSV의 유효 CD·D0 확인으로 고쳐 재실행했습니다. 이 assertion 실패를 계산 실패로 숨기거나 오인하지 않습니다.

기본 **Focus/Dose Sweep은 꺼져 있습니다.** 전체 Sweep은17focus×21dose지만 dose마다 FFT를 다시 하지 않습니다. 실제−0.2/+0.2µm의 CPU 비용을6ROI×17focus·0.1CPU로 환산하면 보통/정밀은 광학만 약22–30분 규모입니다. 이는 전체 Sweep 실측이 아닌 규모 추정이며, 300초 동기 요청에 적합하지 않습니다. 새 조합의 전체 HTTP·실제 Render 실행은 미검증입니다.

<h2 id="validation">10. 구현·테스트·재현</h2>

추가 코드는 `src/benchmark/`와 실험 CLI이며, 기존 Production API·물리 모델을 유지합니다. Analytical Reference, Exact Polygon Coverage/SSAA, 여섯 보간법, 선택적2D Abbe 검증, 독립 Mask/Field Grid, 비교표 exporter와 재시작 checkpoint를 포함합니다.

- **전체 회귀192개 통과**, 별도 Render 자원 검토 관련40개 통과 및 기존 전체 HTTP smoke PASS.
- Constant/Sine/Nyquist·원 Sample 보존·Kernel 정규화·Boundary·Ringing, Rectangle/면적·SSAA·Translation/Hole/Periodic, Analytical↔FFT·Raw Scale·Threshold/CD를 검증했습니다.
- 작은24² Grid의 같은 Discrete Source에서 Abbe↔Full-rank SOCS 최대 잔차4.44e−15를 확인했습니다. Source 수와 유효 SOCS mode 수는 같다고 가정하지 않았고, truncation 오차는 동일 Discrete Source Abbe 대비로 계산했습니다.
- 상용 TCC1024×1024 Grid를 재현하지 않았습니다. GeoSignal의 `max_frequency_count=1024`를 상용 TCC Grid나 Kernel 수와 동일시하지 않았습니다.

다음은 Lab release 소스와 fixture가 있는 환경에서의 재현 명령입니다. Application repository는 비공개이며 이 Pages에는 검토된 합성·공개 TT04 결과를 제공합니다.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -m src.benchmark.full_cross
.venv/bin/python -m src.benchmark.cross_validate
.venv/bin/python -m src.benchmark.split_grid
.venv/bin/python -m src.benchmark.comparison_tables --root . --output work/comparison_tables
.venv/bin/python -m experiments.benchmark_render_feasibility --output work/render_feasibility/native
.venv/bin/python -m pytest -q
```

`configs/benchmark_full_cross.json`, `benchmark_normal_preset.json`, `benchmark_render_feasibility.json`이 각 범위의 물리·수치 조건을 고정합니다. 설정/수치 코드 fingerprint가 일치하는 완료 checkpoint를 재사용합니다. 원본 행 수와 source artifact SHA256는 [manifest.json]({{ '/assets/release-notes/v0.11/manifest.json' | relative_url }})에 있습니다.

<h2 id="limits">11. 한계와 다음 적용 순서</h2>

선택한 주기 Pattern·단일 Contact·nominal focus의 Scalar 모델 연구입니다. 실제 장비 Source·Vector/Mask3D·Resist/PEB/현상·실측 wafer calibration·범용 Contour EPE는 포함하지 않았습니다. TT04는 자원 비용을 검증했으며 독립 연속 Source 기준의 AI/CD 정확도는 미검증입니다. 더 작은 Pixel, 더 높은 Dense, 더 긴 Sinc가 항상 좋다고 가정하지 않습니다.

1. Render 화면·옵션·설정 변경안을 별도 검토하고, Exact Area/B-Spline을 opt-in으로 연결합니다. 같은 raw intensity·좌표·threshold에서 Gauge와 Contour를 일관되게 처리해야 합니다.
2. Area 경계 Cell 최적화와 Source/Mask/FFT cache를 먼저 검증합니다. 기존 Bilinear/Binary와 회귀 비교를 유지합니다.
3. 보통 Cell-area51/Mask10/AI25를 nominal·소수 ROI에서 E2E 검증합니다. Native AI metadata를 Mask metadata와 분리해야 합니다.
4. 정밀 Mask5는 별도 Mask cap와 메모리 budget을 둡니다. 기본 ROI/ambit를 줄여 같은 실험처럼 비교하지 않습니다. 전체 Sweep은 유료 compute 또는 비동기 작업에서 별도 측정합니다.

이번 릴리즈는 이러한 제품 변경을 미리 적용하지 않습니다. Lab은 `release/v0.11.0`/`v0.11.0`으로 보존하고 Render 연결 `main`은 유지하며, Pages만 새 릴리즈 노트를 게시합니다.
