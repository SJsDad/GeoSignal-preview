# v0.12 — 6f Ray and Wave Simulator

v0.12 adds an educational **6f ray-tracing and Fourier-optics simulator** directly to GitHub Pages, with separate English and Korean screens. The learning notes, research reviews and navigation now have matching language counterparts.

[Open the English simulator]({{ '/simulator/' | relative_url }}) · [Read the optical principles]({{ '/notes/diffraction-defocus/' | relative_url }})

## 1. Rays first, waves linked to the same orders

The main view follows Source 0f → Condenser 1f → Mask 2f → Objective 3f → Pupil 4f → Imaging lens 5f → Wafer 6f. Equal-focal-length thin lenses collimate illumination and focus each diffraction order to one pupil position. Blocked rays stop at the pupil; transmitted orders form an inverted image.

The default includes orders 0 and ±1. Pupil amplitude/phase, complex field and wafer intensity use the same selected diffraction orders and transmission rules. Presets compare normal three-beam, symmetric two-beam and higher-order cases. Expanded controls support duty ratio, orders up to ±32, wavelength, pitch and paraxial or scalar angular-spectrum phase.

## 2. Runs directly on Pages

HTML, JavaScript and Canvas perform interactive calculations in the browser without calling the Render API. A separate Worker calculates the optional through-focus map when expanded. This removes the simulator's Render cold-start wait; initial page/asset downloads still depend on the connection and browser.

GDS/OAS uploads and layout analysis continue to use the Python/Render service. The simulator's Python reference engine and API remain available for numerical comparison; this version does not deploy the v0.11 sampling candidates into the layout-analysis interface.

## 4. Documentation parity

The English Abbe, Fourier-optics and diffraction/defocus notes now include the derivations and examples available in Korean. English Hopkins/TCC/SOCS and inverse/metrics pages, eight research reviews, the overview, scope and source-access notes complete the language pairs. Both languages retain the same 55 figure-source records and the same access/verification limits.

Common language links, language-aware demo buttons, catalogs, breadcrumbs and previous/next paper links keep readers on the corresponding language path. Release indexes and Home link this version explicitly.

## 5. Validation and maintenance

Validation covers Python/browser numerical agreement, thin-lens ray matrices, both simulator languages, state-preserving language links, presets, pupil blocking, optional Worker maps, mobile layouts and static operation without Render requests. Jekyll checks verify counterpart routes, generated links/assets and figure-source parity.

The application repository exports both Pages screens from the shared template, defaults and browser assets. An export check detects stale copies; the public manifest records file hashes. The mathematical engine is shared between languages, so translations do not introduce separate physical implementations.

## 6. Model limits

This is an idealized thin periodic 1D mask, one coherent source point and a uniform air medium. Rays remain paraxial. Angular-spectrum phase is a scalar option, not vector/high-NA scanner or mask-3D validation. Ray-drawing focus displacement is magnified ×2000 for visibility; wave calculations use physical µm.

Symmetric two-beam focus invariance is an ideal interference result, not infinite process DOF. The through-focus intensity map is not a CD/Bossung curve. Finite sources, resist chemistry, manufacturing rules and wafer calibration require separate models and validation.
