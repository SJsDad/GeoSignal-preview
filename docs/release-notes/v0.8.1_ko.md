# v0.8.1 릴리즈 노트

## 주요 내용

v0.8.1은 v0.8 process-window result contract를 보존하면서 반복 계산을 줄이고,
추가 aerial-image 구현을 연결할 수 있는 안정적인 integration seam을
마련했습니다.

## Backend-Neutral Imaging Contract

Application은 mask와 optical configuration으로 imaging context를 준비한 뒤,
요청한 physical focus의 raw aerial image를 계산합니다. Abbe는 reference
implementation으로 유지합니다. Contract는 다음을 보존합니다.

* raw, non-peak-normalized, clear-field-relative intensity
* micrometre 단위 wafer-side focus
* effective source-sample count
* calibration과 process-window orchestration의 backend-neutral reuse

이 contract는 service workflow에 backend별 분기를 추가하지 않고 v0.9의 exact
Hopkins 구현을 연결하는 지점이 됐습니다.

## 성능 및 진단 정보

v0.8.1에서는 다음을 개선했습니다.

* preview, calibration, sweep 사이에서 raw best-focus aerial image 재사용
* 무조건적인 31-point calibration을 guarded coarse bracketing/refinement와
  exhaustive fallback으로 교체
* dose condition별 raw aerial-image copy 제거
* printed-contour measurement의 uniform coordinate lookup 가속
* calibration search, evaluation count, boundary, tolerance state 기록
* 안전한 public error는 유지하면서 internal geometry failure logging

Baseline `320 x 320`, candidate 1개, 3-by-3 benchmark에서 runtime은 `4.30 s`에서
`2.94 s`로 줄었습니다. 이는 개발 장비의 측정 비교이며 hosting latency를
보장하는 수치는 아닙니다.

## 검증

v0.8의 dose-to-size result, PASS/status grid, sampled depth of focus,
representative measured-CD signature를 보존했습니다. Merge된 v0.8.1 release
revision에서 자동화 test 50개를 모두 통과했습니다.


## 보존된 평가 자료 상세

아래 그래프는 당시 보고서에 남은 수치를 다시 시각화한 것입니다. 새 실행이나 현재 버전의 benchmark가 아닙니다. CSV는 보존된 표의 전사본이며 원시 반복 측정 trace는 아닙니다.

### 조건과 해석

위 v0.8 baseline과 동일한 synthetic preset의 unprofiled 단일 실행 비교입니다. 결과 signature는 보존되었고 production-shape smoke는 4.30→2.94초였습니다. Medium은 2.10→2.07초로 개선이 작았습니다. 해당 case에서 calibration fast path의 단조성/bracket 조건이 성립하지 않아 exhaustive fallback을 사용한 것이 이유입니다.

Best-focus raw image를 preview·calibration·focus-zero sweep에서 공유해 C개 candidate와 F개 focus의 aerial 계산을 C+1+C×F에서 C×F로 줄였습니다. Calibration은 당시 0.05 간격 grid를 유지했으며, v0.10의 0.1 nm fitting tolerance refinement와 같은 의미가 아닙니다. Peak working set은 약 226~249 MiB였습니다. 동기 full-default 요청이 실시간으로 완료된다는 보장은 하지 않습니다.
